How Handy is designed

1. The whole

Handy is a Tauri desktop application. Rust owns the operating-system integration and transcription pipeline. React presents onboarding, settings, model management, history, and status. Tauri commands carry UI requests into Rust; events carry status and errors back. Startup source · UI source

2. The pieces

P1Startup and UI boundary

main.rs parses CLI flags and calls lib::run. The Tauri setup creates managers, registers typed commands and events, and builds the main window. After onboarding, React calls commands to initialize keyboard simulation and shortcuts. This timing is intentional for permission prompts. Entry point · Managers · Onboarding gate

P2Shortcut state

Keyboard and external triggers feed one coordinator thread. Its state tracks idle, recording, and processing. It interprets toggle and hold behavior, debounces input, and remembers some presses that arrive while processing. The coordinator emits start and stop effects to the action layer. Shortcut handler · States · Thread

P3Audio and recognition

The recording manager owns microphone lifecycle and forwards frames to a streaming router when applicable. The audio toolkit handles capture, resampling, and VAD. The transcription manager loads and runs Whisper-family engines through transcribe-cpp and ONNX engines through transcribe-rs. On stop, usable stream text wins; otherwise the full samples are transcribed in a batch. Audio manager · Engines · Finalization

P4Storage and output

Settings use Tauri's store; downloaded models live in app data; history records use SQLite and recorded audio uses WAV files. After recognition, an optional post-processing path can change the text. The action layer stores history and pastes nonempty final text into the active application. Settings · Models · History · Output
