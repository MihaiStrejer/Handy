# Processing messages: runtime design

Status: Proposed implementation design for the agreed [message specification](../components/processing-messages.md) and [review decisions](../processing-messages-review.md). The running application still sends a JSON user-message envelope. This document defines runtime contracts; the companion [migration and integration design](processing-messages-migration.md) and [verification plan](processing-messages-verification.md) cover storage changes and proof.

## Current seams and ownership

[`SessionStore`](../../src-tauri/src/context_profiles/session.rs) freezes one `ResolvedContext` per recording, [`capture.rs`](../../src-tauri/src/context_profiles/capture.rs) reads bounded input state, and [`routing::resolve`](../../src-tauri/src/context_profiles/routing.rs) chooses one profile and copies its long-term memory and memory. [`request::process`](../../src-tauri/src/context_profiles/request.rs) currently assembles the JSON envelope, runs the synthetic compatibility probe, sends the rewrite request, validates the response and rechecks input. [`actions.rs`](../../src-tauri/src/actions.rs) schedules output on the main thread, while [`clipboard::paste`](../../src-tauri/src/clipboard.rs) owns paste methods, delays, clipboard handling and auto-submit. Keep these owners and the existing endpoint path; add no second insertion coordinator.

The symbols in the tables and Rust sketches below are **proposed**, unless marked existing. Exact Rust names may change during implementation, but their states and ownership must remain explicit.

## Frozen capture contract

Replace the inference from `selection: Captured<String>`, `surrounding_text`, `caret_utf16` and `truncated` in existing [`InputContext`](../../src-tauri/src/context_profiles/session.rs) with an explicit field extent and selection state. Keep the existing application, workspace and capture timestamp fields. `TargetIdentity` remains local to the session and never enters provider messages or ordinary logs.

Add frozen prompt readiness to `ResolvedContext` alongside its owned prompt text. Existing [`routing::resolve`](../../src-tauri/src/context_profiles/routing.rs) validates the prompt and fails resolution on invalid syntax; under the migration design, a saved `needs_review` prompt must instead resolve as a typed, non-dispatchable context. This lets `request::process` record profile provenance and return an actionable prompt-review error before classification or provider work. It must not wait for the generic unresolved-session timeout. The [migration design](processing-messages-migration.md) owns the stored review state and editor transition.

```rust
// Proposed values carried in InputContext; offsets count UTF-16 code units from field start.
struct Utf16Range { start: u32, end: u32 } // start < end for a selection
enum FieldExtent { Full { utf16_len: u32 }, Prefix { utf16_len: u32 }, Unavailable }
enum SelectionCapture {
    NoSelection { caret_utf16: Captured<u32> },
    Verified { range_utf16: Utf16Range, text: String },
    KnownNonemptyUnverified,
    Unknown { reason: CaptureUnknownReason },
    Protected,
}
struct FieldCapture { text: Captured<String>, extent: FieldExtent }
```

`NoSelection` means the adapter established that no characters are selected; its caret can still be unavailable. `KnownNonemptyUnverified` means the adapter established a nonempty selection but could not verify its text or range. `Unknown` means selection presence itself is unknown and retains the existing unavailable, uncertain and timed-out distinctions as a reason. `Protected` on any captured input field blocks the request before a provider call. A zero-length native selection becomes `NoSelection`, never a `Verified` range.

The adapter supplies absolute offsets from the focused field, not positions found by searching selected words. On Windows native Edit, `EM_GETSEL` already yields start and end; carry them through the native fallback in [`capture.rs`](../../src-tauri/src/context_profiles/capture.rs). For UI Automation TextPattern, derive and verify absolute endpoints against the same document and selected range; if the adapter cannot prove them, return `KnownNonemptyUnverified` when it knows a nonempty selection exists. Do not use a selected-text search or a guessed range. A prefix capture starts at field offset zero. Existing `SURROUNDING_LIMIT` of 4096 Unicode scalars, `SELECTION_LIMIT` of 2048 scalars and 250 ms capture deadline remain. Unsupported controls and non-Windows adapters keep truthful unavailable states.

Before a captured field is used, verify that `FieldExtent::Full` accounts for the entire field and that `FieldExtent::Prefix` is labeled as a prefix. Convert UTF-16 offsets by walking Rust `char` boundaries and accumulating `len_utf16()`; accept an offset only when it equals a scalar boundary and lies within the captured extent. For a selection wholly inside captured text, require the range's exact slice to equal the separately captured selection, including spaces and line endings. For selection-only Edit, require the adapter's independent absolute range and complete selected text, with its UTF-16 length matching the range. An invalid endpoint, inconsistent field, or oversized selection blocks editing; never round an offset or recover a position by text search. These checks cover repeated text, emoji, combining characters and selected boundary whitespace.

## One classification for the whole run

Add a pure `classify(&InputContext) -> Result<RequestClass, ContextError>` after the frozen context, prompt readiness and transcript checks. `RequestClass` is the sole source of the expected response operation, History classification metadata and output authority. Its internal `ContextFree` case is a degraded rewrite path, not a fourth editing intent. The public `request_type` is null for that case.

| Ordered condition                                                                 | Proposed class and mode                             | Output proof                                                               |
| --------------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------- |
| Any protected captured field                                                      | Recoverable error before provider work              | None                                                                       |
| Verified nonempty selection and exact range mapping into a full field             | `EditSelection`, `full`                             | Target, range, selected text and field text                                |
| Verified nonempty selection and exact mapping into a retained prefix              | `EditSelection`, `excerpt`                          | Target, absolute range, selected text and retained prefix                  |
| Verified nonempty selection with independent range but no usable surrounding text | `EditSelection`, `selection_only`                   | Target, absolute range and selected text                                   |
| Known nonempty selection without verified text and range                          | Recoverable edit-context error before provider work | None                                                                       |
| Verified no selection and a complete empty field                                  | `NewMessage`, `full`                                | Target, empty field and no selection                                       |
| Verified no selection, nonempty full field and a valid caret                      | `ContinueMessage`, `full`                           | Target, caret and full field                                               |
| Verified no selection, nonempty prefix and a valid caret within it                | `ContinueMessage`, `excerpt`                        | Target, absolute caret and prefix                                          |
| No usable field/caret context and verified no selection                           | `ContextFree`, `context_free`                       | Target and verified no selection; final focus and selection check required |
| Unknown selection presence                                                        | `ContextFree`, `context_free`                       | Candidate only; no automatic paste                                         |

Selection takes precedence even when it covers the whole field. Whitespace-only text is nonempty. A caret in the middle and a caret at the end both select Continue. A verified selection outside the retained prefix may take the selection-only path only when its absolute range and complete text are independently verified. A missing or invalid caret with verified no selection falls to context-free guidance rather than pretending the field is empty or the cursor is at its end. `RequestClass` carries frozen `DispatchProof` data or an explicit candidate-only state; a model response never adds authority.

## Message assembly

Add a `PreparedRequest` produced by `render(&ResolvedContext, transcript, &RequestClass)` after classification metadata is recorded. The proposed value contains `class: RequestClass`, `system: String`, `user: String`, `expected_operation: TextOperation`, `dispatch_proof: DispatchProof`, `request_type: Option<RequestType>`, `context_mode: ContextMode` and a constant `request_template_version`. Do not recompute classification in response parsing, History or output. `NewMessage`, `ContinueMessage` and context-free requests expect `insert`; `EditSelection` expects `replace_selection`.

[`template.rs`](../../src-tauri/src/context_profiles/template.rs) currently permits four placeholders and renders each as a JSON field reference. For profile system prompts, accept zero or one `{{long_term_memory}}` placeholder and reject old dynamic placeholders, repeated long-term memory placeholders and unsupported syntax before assembly. Preserve one-pass rendering: parse the configured prompt once, insert already serialized long-term memory text once, and never scan inserted values for template expressions. If no placeholder exists, append the same labeled long-term memory block. The system message is the rendered owned profile prompt followed by the fixed response contract; that contract describes readable user sections and the existing `text`, `operation`, `memory_changes` response without referring to a JSON user envelope.

Render the selected profile's long-term memory string exactly once inside deterministic labeled boundaries. Preserve its order and scoped prose; there are no keyword IDs or alias collections. Choose boundaries by scanning the configured prompt and the frozen long-term text, advancing a counter on collision. State empty memory explicitly. Never reinterpret memory as template syntax. The renderer reads no transcript, short-term notes, field text or user-message marker, so those inputs cannot change system bytes.

Render the user message from Handy-owned task text and the classified context. Use the agreed New, Continue, Edit and degraded wording in the [specification](../components/processing-messages.md); excerpt and selection-only variants explicitly state what is missing. Omit empty optional memory or context sections. Include dictation in every request, under `spoken_instruction` for Edit and `dictation` otherwise. Render memory items as quoted reference values in their frozen order; memory and field text never become instructions or system-prompt substitutions.

Choose user section and cursor/selection tokens deterministically from all raw values to be inserted, including transcript, memory and captured text. For example, try `⟦HANDY_0_INPUT_START⟧`, `⟦HANDY_0_INPUT_END⟧` and the needed cursor or selection tokens; increment the shared number until none of that candidate's tokens appears in any raw value. Insert exact captured text between the chosen tokens. Name the actual tokens in the task guidance, and use the same collision rule for memory and dictation boundaries. A captured `</input_message>`, marker string or `{{transcript}}` remains literal content. Token selection changes only the user message; the system message stays byte-identical for an unchanged prompt and long-term memory.

Reject an empty transcript, a transcript over 32000 Unicode scalars, an invalid prompt, and any protected capture before endpoint work. After rendering, use checked addition for `system.len() + user.len()` and reject a total over 512000 UTF-8 bytes; do not prune long-term text, memory, selected text or custom prose. Preserve the existing 128000-byte response limit and 32000-scalar nonempty prediction limit. The separate archive limit applies later to the complete transport JSON body, not to this two-message content budget.

## Provider, response and History path

The proposed order in [`request::process`](../../src-tauri/src/context_profiles/request.rs) is: take the existing single-use session snapshot; record owned-profile provenance, prompt/long-term memory revisions and the current template version on the run; check prompt readiness, transcript and protected capture; classify once and record `request_type` and `context_mode`; render and check the combined message budget; call `ensure_compatible`; send the existing HTTP chat-completion request; parse against `PreparedRequest.expected_operation`; record the candidate and validated memory proposals; then perform the existing preflight input recheck. A prompt awaiting review or a known nonempty unverified selection leaves type and mode null; context-free classification records a null type with `context_free` mode. Compatibility probing stays synthetic, carries no profile content and uses the updated response contract. Validation or budget failure must occur before even that probe. [`llm_client::send_chat_completion_observed`](../../src-tauri/src/llm_client.rs) already builds one system and one user message and archives the exact serialized request body through `RunGuard::start_call`; keep that transport and its archive preference.

Change `parse(content, selection)` to `parse(content, expected_operation)` so a selected-text value cannot independently decide which operation is allowed. Keep strict JSON parsing, proposal shape validation and size checks. An `insert` from an Edit request or `replace_selection` from any other class is invalid. JSON responses and `submit_rewrite` arguments retain the MR correction-proposal validator, staged batch and exact-readback admission gate. This message delivery adds no new learning authority or long-term write route. Keep History's candidate even when a later output check blocks insertion. The History implementation document owns the new nullable columns, archive clearing behavior and migration; runtime assembly supplies `request_type`, `context_mode`, template version and prompt/long-term memory revision values before compatibility checks.

Treat a known nonempty unverified selection, protected input, invalid range and oversized message as recoverable processing failures with local error codes and no provider request. Treat unknown selection as a valid context-free request whose returned candidate is withheld from automatic output. Do not expose provider errors, captured text or prompt contents through error messages. Existing [`failure_code`](../../src-tauri/src/context_profiles/request.rs) must map new pre-provider failures deliberately rather than leaving them as undifferentiated `processing_failed` when the UI needs to explain a blocked edit or prompt review.

The ordering above requires an attempt to save provenance before provider work, not guaranteed persistence through a database failure. Preserve History's best-effort policy: a missing run or failed metadata write triggers the existing visible details warning and incomplete state where possible, while processing may continue using the same frozen in-memory classification and output proof. Never infer insertion authority from History persistence. The migration document specifies null initial profile-prompt provenance and transactional archive revocation; runtime observations must use those gates rather than a stale in-memory archive permission.

## Output authorization and exact paste text

The current preflight [`input_unchanged`](../../src-tauri/src/context_profiles/request.rs) compares selection text, field text and caret but not range or extent. Compare the full frozen proof instead: target identity, selection state, absolute range or caret, captured field text and extent, and any protected status. A failure leaves the model's candidate in History and returns an output block. The preflight is useful but does not replace the final check because [`actions.rs`](../../src-tauri/src/actions.rs) queues paste later.

Keep the existing main-thread dispatch and [`clipboard`](../../src-tauri/src/clipboard.rs) paste implementation. Pass a profile-only exact-text mode and a one-shot final-guard callback through that path. The callback verifies that the same session/generation and target remain current, takes one bounded capture through `CaptureService`, and compares the required `DispatchProof`. Run it after the configured `paste_delay_ms` and immediately before the first paste gesture, with no further asynchronous queue. A timeout, stale session, changed caret/range/text, protected field, unknown selection or unsupported target blocks dispatch. For context-free output with verified no selection, final focus and no-selection evidence suffices even when field text was unavailable. Context-free output with unknown selection remains candidate-only regardless of the model's `insert` operation. Native checks reduce the race window; they cannot lock another application's editing state atomically.

The existing legacy clipboard path sleeps before its paste chord; put its profile guard after that sleep and before key injection. Direct typing checks before its first key; it cannot guarantee target stability through every simulated keystroke. Reliable paste needs a guard after publication and immediately before `send_chord` in [`paste_tx/windows.rs`](../../src-tauri/src/paste_tx/windows.rs) and [`paste_tx/macos.rs`](../../src-tauri/src/paste_tx/macos.rs); a failed guard after publication must cancel or restore that transaction without injecting a chord or auto-submit. Give guard rejection a distinct result from reliable-paste unavailability: the current [`clipboard::paste`](../../src-tauri/src/clipboard.rs) fallback on any reliable-paste error must never retry a rejected guard through the legacy path. If a paste method cannot honor this guard, withhold profile output and retain its candidate. The current external-script method gives an arbitrary script control after launch, so it has no supported final-guard contract for profile output; ordinary external-script paste remains available. `PasteMethod::None` records a skipped dispatch and never auto-submits.

Profile exact-text mode bypasses the `append_trailing_space` branch in [`clipboard::paste`](../../src-tauri/src/clipboard.rs), including copied-to-clipboard output, while ordinary transcription retains that setting. Keep the user's explicit `auto_submit` preference and existing submit key path; text dispatch and later submission are separate outcomes in verification. A blocked final guard must not submit. Keep the existing clipboard restoration and error handling for each supported method. Do not create a second output queue or infer success from an accepted provider response.

### Reliable paste timing and rejection

For guarded profile paste, apply the configured pre-paste delay exactly once before starting reliable clipboard publication. Then publish, perform the bounded final guard and inject the chord. The current reliable-paste API has no delay argument, so the guarded caller must explicitly arrange this ordering. Do not sleep for the configured delay after publication: the reliable transaction's eight-second timeout starts at publication. If reliable paste is unavailable before dispatch, an eligible legacy fallback uses the already-paid delay and its own final check; it must not double the delay or reuse a consumed guard. Ordinary paste timing remains unchanged.

Use a proposed typed guarded outcome such as `Dispatched`, `Skipped` or `Blocked(reason)`, distinct from operational paste errors. The guarded entry point in the existing clipboard owner returns this outcome to `actions.rs`; retain a compatibility wrapper for ordinary callers. `Blocked` preserves the processed candidate, records the existing applicable blocked-output code or a new localized code, and never reaches legacy fallback or auto-submit. It must not be flattened into `Result<(), String>` and recorded merely as a generic paste failure.

A reliable guard rejection after publication requires a dedicated abort path. Mark it as never injected, suppress all submit paths, and restore the prior clipboard only if this transaction still owns it. This abort overrides `ClipboardHandling::CopyToClipboard`; ordinary settlement currently preserves the candidate in that mode and is not sufficient. Do not overwrite a clipboard value published by another owner in the meantime. The worker must acknowledge abort/cleanup so a later timer or cancellation handler cannot restore or preserve the candidate again. Test this state independently of ordinary reliable unavailability and injection failure.
