2. Handy checks the reply and destination

  1. Is the reply valid?Check required fields, text and effect limits, and whether the operation matches the captured selection.
  2. Does this recording still own the result?Reject cancelled or superseded sessions. Recheck selection, surrounding text and caret where capture is supported.
  3. Is the original input still focused?Check the session again and compare the destination immediately before output.

These are acceptance conditions, not a claim that every check runs only once. Cancellation and session identity are checked at multiple points. A cancellation cannot undo output already dispatched.

Keep persistence in its own section

“What survives the next recording?” is a separate architecture question. Keep its existing explanation after the output section, under its own heading, instead of treating it as another output check.

  • Saved profiles and manual dictionary edits remain available. Each new recording captures context again.
  • Short-term memory and endpoint compatibility state last for the app process; automatic memory population is not implemented.
  • When audio saving succeeds, history may be saved before output. A history entry does not prove insertion and is not replayed as a model conversation.
