04 · P5 · Check the reply

Accept a strict prediction

{"text":"Open Codex and review the changes.",
 "operation":"insert",
 "effect":{"type":"none"}}

The reply must have valid fields, nonempty bounded text, a valid effect, and an operation matching the captured selection. Unavailable selection permits insertion, never replacement.

For supported fields, selection, surrounding text and caret are rechecked before acceptance. The session must still be current.

Five changes to that same story

Each strip compares a concrete cause with the blocked stage and the resulting experience. Every exception stays visible.

ExceptionBEFORE / CAUSEBLOCKED STAGEAFTER / EXPERIENCE

Cancellation
Session guard

Before / cause

The request is in flight. You cancel before output.

Blocked stage

04–05 · Accept / pasteCancelled or stale work cannot attach to a newer session.

After / experience

The pending result is not inserted. A later recording starts independently. Work already sent may finish remotely.

Focus change
Focus guard

Before / cause

You started in Terminal, then focus a different window before dispatch.

Blocked stage

05 · PasteThe current Windows destination no longer matches the original.

After / experience

No output is redirected to the new window. Handy emits “Input focus changed… output was not inserted.”

Field change
Field recheck

Before / cause

In a supported native Edit field, “cloud code” was selected. You change its text, selection or caret while waiting.

Blocked stage

04 · Accept predictionThe reread differs from the original supported field snapshot.

After / experience

Your newer edit stays. The replacement is not inserted; Handy emits an input-changed error. This check cannot cover unavailable fields.

Invalid reply
Strict parser

Before / cause

The endpoint returns prose, an unknown field, empty text or replacement without a verified selection.

Blocked stage

04 · Parse responseThe strict JSON or operation contract fails.

After / experience

No raw JSON or prose fallback is pasted. Handy emits a transcription error.

Protected input
Protected capture · Assembly guard

Before / cause

The original native Edit field is marked as a password input.

Blocked stage

03 · Assemble requestCapture marks protected input; request assembly rejects it.

After / experience

No profile request containing this session’s context is sent. No output is inserted; Handy emits a protected-input error.

Error emission is code-derived. Exact notification appearance and live timing are not demonstrated here. Cancellation means before output dispatch; it cannot undo text already inserted.

G1 · P7 · Undecided

When can a correction become learning?

Suppose the reply proposes remembering “codecks → Codex.” The missing link is evidence that the intended field received the intended result. The current code stops at the proposal. T07 decision gate

Paste dispatched → [completion evidence missing] → apply learning

Proposed future behavior. No option below is implemented or approved.

G1-A · Recommended

Read back the field

Learn after a supported destination matches the expected result.

Benefit: ties learning to actual output.

Cost: verification work; unsupported targets cannot learn automatically.

G1-B

Ask the user to confirm

Let the user approve the learning action explicitly.

Benefit: covers targets without readback.

Cost: interrupts the flow with an extra interaction.

G1-C

Trust successful dispatch

Learn when the paste call reports success.

Benefit: simplest integration and broad coverage.

Cost: can learn even if text never arrived; weakens the completion requirement.

Answer: pending. Recommendation: G1-A. No decision is recorded by viewing this page.

A chosen completion rule still needs semantic feedback validation, persistence, stale/duplicate protection and a demonstrated next request carrying the accepted update.
