After / experience

Field recheck

Before / cause

In a supported native Edit field, “cloud code” was selected. You change its text, selection or caret while waiting.

After / experience

Your newer edit stays. The replacement is not inserted; Handy emits an input-changed error. This check cannot cover unavailable fields.

Before / cause

Protected capture · Assembly guard

Before / cause

The original native Edit field is marked as a password input.

After / experience

Error emission is code-derived. Exact notification appearance and live timing are not demonstrated here. Cancellation means before output dispatch; it cannot undo text already inserted.

G1 · P7 · Undecided

When can a correction become learning?

Suppose the reply proposes remembering “codecks → Codex.” The missing link is evidence that the intended field received the intended result. The current code stops at the proposal. T07 decision gate

Paste dispatched → [completion evidence missing] → apply learning

Proposed future behavior. No option below is implemented or approved.

G1-A · Recommended

Read back the field

Learn after a supported destination matches the expected result.

Benefit: ties learning to actual output.

Cost: verification work; unsupported targets cannot learn automatically.

G1-B

Ask the user to confirm

Let the user approve the learning action explicitly.

Benefit: covers targets without readback.

Cost: interrupts the flow with an extra interaction.

G1-C

Trust successful dispatch

Learn when the paste call reports success.

Benefit: simplest integration and broad coverage.

Cost: can learn even if text never arrived; weakens the completion requirement.

Answer: pending. Recommendation: G1-A. No decision is recorded by viewing this page.

A chosen completion rule still needs semantic feedback validation, persistence, stale/duplicate protection and a demonstrated next request carrying the accepted update.
