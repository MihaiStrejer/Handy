What repeats when you speak again?

02

Where reuse could happen

Implemented today

Two fresh messages per utterance

system

Rendered effective profile prompt followed by the fixed response contract.

user JSON

Dictionary, short-term memory, input context, and transcript. The dictionary is user data today, even when unchanged.

response

The client parses the first returned message content. It does not parse cached-token usage or set explicit prompt-cache control.

Proposed, not implemented

Put reusable data first

stable

Arrange stable instructions and stable profile reference data as an identical prefix across eligible requests. Keep dictionary content as untrusted data, even if the message layout changes.

dynamic

Append current memory, input context, and transcript after that prefix. A profile or dictionary edit may change the prefix.

measure

Record provider reported cached usage, if available, then compare latency and billed input. Eligibility and savings depend on the provider, model, request shape, and timing.

Boundary to test: a layout that groups stable dictionary data before dynamic fields would reshape the current single user JSON envelope. It need not change the dictionary data role. Preserve the rule that reference data is untrusted, verify equivalent model behavior, and fall back cleanly when a provider has no compatible cache. Matching text alone does not establish a cache hit.

No provider-specific cache behavior is claimed here. Current assembly · Current client.

G1 · Open · Learning after output

What counts as successful output before a proposed correction is remembered?

The endpoint can propose an effect, but no automatic writer applies it. A successful paste call reports dispatch, not readback from the destination. A correction learned from A could change B’s data, so the completion rule also affects reuse boundaries.

Concrete case: A proposes remembering “use Codex.” Dispatch succeeds, but the destination has not been read back. Should B receive that correction?

G1-A · Recommended

Read back the result

Learn after supported fields contain expected output. Stronger evidence; unsupported targets cannot learn automatically.

G1-B

Ask the user

Works where readback is unavailable; interrupts dictation.

G1-C

Trust dispatch

Broad coverage and simple implementation; may learn when output did not arrive.
